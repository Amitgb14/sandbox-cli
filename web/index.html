Containment for coding agents

Your agent gets root.
It just doesn't get your machine.

sandbox-cli runs Claude Code, Codex, Gemini and twelve more agents inside a disposable container. Only the project you point it at is mounted. Everything else — your SSH keys, cloud credentials, the other 200 repos on your disk — simply isn't there to reach.

The trade nobody should have to make

“Allow All” is the useful mode. It's also the dangerous one.

Agents earn their keep when they stop asking permission for every edit. But the same flag that unblocks the work hands a non-deterministic process your entire home directory — and prompt injection turns someone else's text into your shell.

Agent on the bare host
  • Reads ~/.ssh, ~/.aws, tokens, browser cookies
  • One wrong path and the blast radius is your whole disk
  • A poisoned README becomes arbitrary local execution
  • Trust is enforced by asking the model nicely
Agent inside sandbox-cli
  • Those paths were never mounted — nothing to read
  • Blast radius is /workspace: the repo it was editing anyway
  • Injection lands in a container that dies on exit
  • Trust is enforced by the kernel, not by the prompt

What holds the line

Guarantees you can read the source of

Every isolation decision funnels through one pure function that turns config into a docker argv. It's unit-tested against a golden output, so the boundary can't drift silently.

One choke point, exhaustively tested

runtime.BuildArgs is a pure function: config in, docker argv out. No hidden state, no side channels. Print it before you run it.

sandbox-cli run --dry-run -- npm test # → docker run --rm -v /you/proj:/workspace …

Refusals you cannot override

Mounting /, your home directory, or any ancestor of it is rejected outright — not warned about, not gated behind a flag. There is no --force.

sandbox-cli run --mount ~ -- bash error: refusing to mount host home

Disposable by default

Every run is --rm. No residue, no drifting state, no container to remember to clean up.

HOME is a decoy

HOME=/sandbox/home, always. Tools that scribble in the home directory find an empty, throwaway one.

Non-root, and it matters

Runs as an unprivileged user. On macOS, mount ownership is virtualized so your files stay yours.

Logins that survive, isolated

Each agent authenticates into its own sandbox-owned home — persistent across runs, and never your real config.

Egress on a leash

Scope the network with --allow so the agent reaches its model API and nothing else.

Many agents, one repo

--worktree gives each agent its own branch and its own sandbox. Run four in parallel without collisions.

Get started

Install once. Prefix your agent. Done.

Needs Docker (Docker Desktop on macOS). Go 1.25+ only if you build from source.

# macOS / Linux
curl -fsSL https://raw.githubusercontent.com/Amitgb14/sandbox-cli/main/install.sh | sh

# …or from source (Go 1.25+)
make install

# optional: scaffold a per-project config
sandbox-cli init
# sandbox flags first, your command after --
sandbox-cli run -- bash
sandbox-cli run -- npm test

# see for yourself: fake HOME, one mount
sandbox-cli run -- sh -c 'echo $HOME; ls ~; ls /workspace'

# print the docker command instead of running it
sandbox-cli run --dry-run -- npm test
# keys forwarded from your env only when set
ANTHROPIC_API_KEY=... sandbox-cli claude
OPENAI_API_KEY=...    sandbox-cli codex exec 'run the tests'
GEMINI_API_KEY=...    sandbox-cli gemini --yolo

# the flag everyone's nervous about — now boring
ANTHROPIC_API_KEY=... sandbox-cli claude --dangerously-skip-permissions

# everything after the agent name forwards verbatim
# each agent gets its own branch, worktree and sandbox
sandbox-cli claude --worktree feature-a -- -p "implement A"
sandbox-cli codex  --worktree feature-b

# inspect and clean up
sandbox-cli worktree list
sandbox-cli worktree rm feature-a

# live CPU / memory gauge in a second terminal
sandbox-cli stats

Per-agent prerequisites, browserless login, and required --allow domains live in the agent reference.
